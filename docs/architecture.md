# Architecture and constraints

Current execution path: operator obtains OpenCellID country download and runs one-shot ingest -> DuckDB analytical quality profile over the raw CSV -> canonical row validation -> idempotent upsert with timestamp guard into PostGIS -> bounded API bbox -> provenance-aware landing page. An explicit second measured-RF table and endpoint are scaffolded but have no source adapters or real observations yet. See knowledge-grades.md. Default MCC 425 is Israel, but set SOURCE_COUNTRY_MCC for other countries. Docker Compose only runs API and DB by default; ingest profile is manually triggered and not automatically scheduled. No live stream, ML model, H3 rollup, object store, actual RF import, or interactive map yet. Do not claim these exist.

Proposed phase 2: persist immutable raw snapshot with SHA-256 manifest; download daily diffs, reconcile deletions against periodic full snapshots; quarantine invalid input; add H3 aggregation with suppression of sparse tiles; MapLibre and locally permissible basemap; opt-in measurement collector with privacy protections and independent license; spatially held-out anomaly evaluation. Redpanda event-time stream and PySpark benchmarking only once representative scale or opt-in observations warrant them.

Do not combine OpenCellID-derived data with other datasets into a public export without reviewing ShareAlike and source rights. Keep code under Apache-2.0 and data under source-specific terms. No employer source, credentials, schemas, internal know-how, or proprietary data.

## Public Pages experiment and next RF stage

The `pages-static` branch now has a browser-only, CC BY 4.0 DoNext H-Bahn RF sample separate from the server `main` architecture described above. Its three map evidence types are: observed `measured_rf` point readings; `model_prediction` H3 hexes from a spatially validated but off-route-untested LightGBM coordinate model; and `estimated_reception_center` markers computed by signal-weighting sampled receiver positions grouped by anonymized MNO, cell_index, PCI and EARFCN. The last are **not physical tower coordinates**; PCI reuse and one rail corridor limit them. No documented mast validation is claimed.

Next stage, when cell/site identities and dependable position ground truth are available: learn signal propagation from each site or sector as a statistical/ML function of **distance and direction** from the site, with technology/frequency and environmental features where licensed data permits. Use sector-aware anisotropic estimates, never isotropic circles. Compare against spatially held-out readings and real site positions, publish errors and uncertainty, and expose propagation as a separate switchable map layer rather than painting predictions as observed coverage. A research prototype can use the current reception-center estimates as noisy anchors, labeled as such, but must not call them towers or claim tower-based validation. Upgrade anchors only after full, matchable cell identifiers and licensed site ground truth are available. OpenCellID supplies *estimated cell positions*, not surveyed masts; verify identifiers and terms before use. Do not merge Pages into `main` merely because the prototype exists.

### Physical-context enrichment after site/sector modeling

Investigate clutter-aware propagation after the sector-aware model is anchored and evaluated. Candidate feature layers include OSM building footprints, SRTM/Copernicus elevation models, and ESA WorldCover land cover. Derive obstruction and terrain-profile features along candidate site-to-receiver paths to explain plausible shadow zones behind buildings or hills. These layers are model inputs, not replacements for RF measurements, surveyed sites, or spatial validation; a satellite image alone cannot prove a blocked signal. Record each source's coverage, resolution, vintage, uncertainty, attribution and reuse terms before downloading or publishing derivatives (notably OSM's ODbL). Test incremental value on geographically held-out routes and report failure cases rather than treating a plausible visual as evidence.

## September 2026 physical-context experiment

A direction-aware, receiver-center-based Dortmund experiment is implemented on `pages-static`, with OSM footprints, ESA WorldCover 2021 and Copernicus GLO-30 DSM. It has a switchable **route-sector diagnostic** only, not a propagation-coverage surface. Spatially blocked pooled MAE worsened from 6.51 dB (direction/distance) to 6.77 dB (clutter features); the separate contiguous route holdout improved from 4.92 to 4.31 dB. No off-route measurements, surveyed towers or building heights are available. See [research, sources, licenses and failures](clutter-research.md) and [metrics](assets/clutter-metrics.json). The next propagation stage still requires identified physical sectors and independent off-route tests.
