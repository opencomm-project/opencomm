# Observational grade, provenance, and jurisdiction

The system separates **inferred_inventory** from **measured_rf**. OpenCellID supplies identifiers, estimated cell center/range, sample count and timestamps, but no usable signal-strength value. The `cells` table and `/v1/cells` response have an explicit `knowledge_grade=inferred_inventory`. Do not call inferred ranges measured coverage.

The `measured_rf_observations` table and `/v1/measured-rf` endpoint support true georeferenced RF/QoS measurements, with `knowledge_grade=measured_rf`, country, source, license, optional measured timestamp and distinct unit-suffixed metrics (RSRP dBm, RSRQ dB, SINR dB, RSSI dBm, latency ms, throughput Mbps). Missing measurements stay NULL, never zero. The measurements are keyed by `(source, source_record_id)`, never by inferred OpenCellID cell ID; their precise source locations and licenses remain attached. Constraints require at least one metric. The API uses bounded bboxes and a required ISO country code; it will return empty arrays until a licensed measured-data adapter is implemented. This is a unified *contract/grade vocabulary* over separate record types, not a false conflation of cell inventories and drive-test samples.

Planned profiles: Israel/OpenCellID inventory by MCC 425; UK/Ofcom annual road drive tests; Germany/TU Dortmund DoNext CC BY 4.0 research snapshot. Exact file schemas, geocoordinate/timestamp semantics, per-file reuse rights and any redistribution limits must be verified from raw files before writing source adapters or loading them. Do not cross-label Germany or UK data as Israeli; do not extrapolate along roads into uncovered areas. Ofcom's generic open-data policy is not proof of each file's exact license. See data-sources.md.

DuckDB in `services/ingest/analysis.py` is the day-one analytical layer on local raw CSV: performs pre-ingest quality counts on raw CSV; the CSV parser passes original, unmodified strings into canonical validation. PostGIS is still the live API's system of record. DuckDB's role will grow to time/technology rollups and source-specific QA once actual licensed raw source samples are verified; none are loaded in the repository. The current code still reads/decompresses an entire file in memory before DuckDB, so it does not solve huge-file memory use yet. Anonymization and spatially held-out validation precede any ML quality claim.
